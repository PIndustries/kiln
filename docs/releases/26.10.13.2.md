# Kiln 26.10.13.2

Kiln adds account sign-in alongside native API-provider profiles. Administrators can connect a ChatGPT registration through the official OSS authorization flow or start Grok CLI device sign-in inside an isolated worker. These paths preserve Kiln's identity, Vault and tool boundaries.

## Changes

- Grok process output uses dedicated blocking I/O threads, preventing concurrent pipe readers from starving one another on Linux. A child-process handshake checks that device codes arrive before exit.

- Native provider profiles cover Erebine, OpenAI Responses, Claude Messages, Grok Responses, DeepSeek Chat Completions and local Ollama.
- ChatGPT accounts use PKCE, one-time state, signed identity validation, encrypted credentials, model discovery, refresh and sign-out. Ownership includes the initiating SSH-key fingerprint. Returning sign-in reuses the account's registration.
- Grok headless workers support API-key and device-account modes. macOS uses sandbox-exec; Linux requires bubblewrap and working user namespaces. There is no unsandboxed fallback.
- Provider acceptance tooling tests a read-only fixture tool round, streamed answer and cancellation through the native router without printing credentials or model text.

## Verified provider behavior

Erebine passed a real fixture tool/result exchange, delivered four answer frames and honored cancellation after incoming content. Local Ollama passed the same check with cached `qwen3:0.6b`, delivering eight answer frames. No model download was required.

OpenAI, Claude, Grok and DeepSeek API-key adapters have protocol fixtures; live checks await account credentials. ChatGPT and Grok account flows await user consent and authenticated end-to-end acceptance. These limits are not waived by a successful build or a callback listener starting.

## Getting started

Use `ai providers` to inspect available provider types. See [AI configuration](../ai.md) for API-key profiles, [account sign-in](../sign-in.md) for the exact login commands, and [provider validation](../provider-validation.md) for the acceptance evidence.

Back up runtime state and the separate Vault master key before upgrading. Account credentials and provider configuration are operator state and are not included in release packages. Host identity and returning-account registrations should remain stable across upgrades.

## Boundaries

This release does not add autonomous coding workspaces, a workflow DAG scheduler, 48 collaborating agents or general shell access for models. Grok CLI workers have no Kiln tools or host project access. Claude and DeepSeek thinking remain disabled in their native adapters. Provider selection does not bypass administrator authorization or mutation approval.

Published asset checksums and platform CI results belong to the GitHub release. This source note does not itself confirm that binaries have been published, installed or deployed.
